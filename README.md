# MetaHotspot

## 当前功能边界

* 异构封装支持+微流道仿真
* 支持对流边界，恒温边界，绝热边界（默认）
* 流体支持压强边界条件

## 总体技术选型

* IO与接口：Python
* 计算核心：当前使用Python+Numba JIT，后续拟迁移到C/C++
* 依赖：`Python`(推荐3.10+), `numpy`, `scipy`, `json`, `meshio`, `numba`

## 当前建模配置方案

* 采取json格式配置2.5D模型。
* Python程序接口接受且只接受一个主配置文件，用于完成整个仿真流程。
* 文件列表：
  * 主配置文件，配置全局参数，仿真类型，材料，层配置（名称，几何，材料，对应的layer配置文件路径，允许属性覆写），边界条件（支持基于单元或层的名称正则匹配）等等。
  * layer配置文件：描述层内单元的名称，几何，也允许材料属性覆写。
  * ptrace文件：功率轨迹，来自上游软件。
* 输出格式：vtu文件（可用Paraview等软件打开）

## 数值技术

* 热模型：CTM（集总热模型），构建一维热阻热容网络（离散方案本质类似FVM/FDM）
* 流固耦合传热：对流-扩散方程计算流体传热+Nusselt数计算流固界面热阻（3D-ICE所采用的方案，应该也是工业标准方案），融入集总热模型中（需要预求解流体压强/速度）。
* 流体的压强信息：当前用泊肃叶流进行近似（模仿Hotspot的处理手段），有待完善。如果求解完整NS方程或者其层流假设版本，都需要u-p迭代，而且网格粒度要求高，计算代价有些大，而泊肃叶流又太过粗糙，或许需要一个更好方案。
* 网格方案：非共形网格（参考ARTSim，但不太一样），对每一个active的层，也就是通常来说产能的层，先生成基于单元的分割，再累次对较长边做切割直到符合要求。但是特别地，在非active的层，我们也先“传染”相邻active层的一部分网格分割，向外才逐渐疏化到max_size。
* 时间步进方法：目前用向后欧拉法（如有必要，后续可以改用误差更小的方法）。
* 非线性：暂未考虑非线性。

## 性能/精度验证

* 在数据结构设计良好，利用numba JIT改善热循环性能的前提下，以Python实现甚至已经能碰瓷原生C/C++软件的性能。
* 当前四个案例：
  * example1（Hotspot原example2）：固体传热（单层硅/TIM/HeatSpreader/HeatSink）
  * example2（Hotspot原example3）：固体传热（3D异构，硅/TIM/硅/TIM/HeatSpreader/HeatSink）
  * example3（Hotspot原example4）：固体传热（3D异构，含硅通孔，硅/TIM/硅/TIM/硅/TIM/HeatSpreader/HeatSink）
  * example4（Hotspot原example5）：流固耦合传热（3D异构，结构复杂）
* 精度验证：
  * 在第1、2、4个案例上，稳态结果和Hotspot基本一致，并且事实上我们的解决方案局部热点捕捉能力更强（接近于ARTSim论文中宣称的使用COMSOL详细有限元仿真的结果）
  * 第三个案例和ARTSim一致，但是显著低于Hotspot（最高温：`~362K(MetaHotspot/ARTSim) vs ~390K（Hotspot）`），到底是它对还是我们对，需要进一步验证。
  * 瞬态当前数值趋势对，但是具体需要进一步验证。
* 效率验证
  * 取决于网格粒度，若只是为取得和Hotspot相近的峰值温度，加速比可以拉到`20~30x`乃至更高。若为了取得一般意义上足够精确的结果，相比Hotspot也有`4~10x`（取决于案例，层次越复杂我们的方案越有优势）的加速比。
