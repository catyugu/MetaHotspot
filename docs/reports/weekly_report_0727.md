## 一、Flotherm 使用的体验

- 单独给一个方块面分配显式的第三类边界条件是没有用的，必须系统里附加相应的 Ambient。若 System 的对应面没有 Ambient，而是 Symmetry、Open 等，则会被直接装配为零通量边界。这里的逻辑和其他 CAE 软件不太一样。
- Flotherm 用的是 FVM 离散格式，在相近网格下，计算的温度确实和用 PTA 或者 COMSOL 中用 FEM 方法计算的结果有一定（甚至有些情形下 2K~3K 往上的）差异。它确实更适合用来作为与我开发的求解器最终比较的基准。借助 Paraview 强大的 resample 功能可以有效比较不同网格下的计算结果。

## 二、其他工作

- 进一步打磨 C API 和 Python 库，使其更加稳定好用。
- 添加对功率轨迹（分片常数周期函数）的支持。
- 支持接入额外自由度和额外方程块（为便于后续实验）。
- 在此案例基础上，对 Spreader 和 Sink 部分做 MPMM 宏模型提取实验，发现：
    - 精度方面，没什么大问题。
    - 端口数量如果很多，MPMM 预处理耗时难以接受，如上例中离散方式 4096 个端口，即使只取三四个采样点，也要上万次全量求解，时间代价万难接受。
    - MPMM 本身不压缩端口模式，因此如果宏模型内部自由度没有明显数量级上大于端口数量，由于存在高度稠密子块，反而对求解效率副作用。有进一步在这方面做改进的做法如 FlexRC, TurboMOR 等，待进一步阅读和实验。
- 担忧：即使算法层面能做好瞬态宏模型的提取，宏模型的存在也会很大程度上改变前端和求解器的逻辑，并可能需要大量修改来适配，短期内可能难以实现很好的集成，功能或许相对死板（例如可能只能在模型定型后提取，修改后需要重新处理）。
